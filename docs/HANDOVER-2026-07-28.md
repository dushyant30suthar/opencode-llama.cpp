## 3. Open actions, ranked

**A1 — Capture the 27B divergence. Free, blocks A3.**
Restart the 27B with `LLAMA_SERVER_SLOTS_DEBUG=1 -lv 1`. Server then logs
`restored context checkpoint (pos_min, pos_max, n_past)` and dumps `old:`/`new:`
tokens at the mismatch. Yields: true longest-common-prefix vs post-checkpoint
`n_past`, the literal text Claude Code mutates, and real per-checkpoint RAM.
Everything about the 2-minute stalls is guesswork until this exists.

**A2 — Compact/clear Claude Code sessions at 48–64k.** Behavioural, free, biggest
practical win. Caps worst-case re-prefill near 2 min instead of 4 and recovers
**+54% decode** (69.1 t/s at 32–64k vs 44.9 at 96–128k).

**A3 — Sweep `--checkpoint-min-step`** (default 8192 → 4096). Halves worst-case
rewind on the hybrid 27B. Each checkpoint is ~144 MiB of recurrent state; 32 of
them ≈ 4.6 GiB already. Measure the real size in A1 first.

**A4 — Drop `spec-type = ngram-mod` from the Laguna-XS profile** in
`models.ini` and `config/models.ini.example`. ngram measures **+0.05%** — noise.
Keep `f16` KV (worth +22% on its own) but fix the comment: the stated reason
("ngram conflicts with quantized KV") is inverted. Zero measurement needed.

**A5 — Fix the `models.ini` comment** claiming MTP requires `parallel = 1`. Not a
llama.cpp constraint — `common_speculative_init(params, n_parallel)` and
`common_speculative_impl_draft_mtp(params, n_seq)` both take a sequence count.

**A6 — A/B 27B `196608 @ q8_0` vs `98304 @ f16`.** Laguna measured f16 KV worth
+22% decode / +15% prefill (quantized KV pays a dequant per attention read).
Roughly VRAM-neutral. Different arch — needs testing, not assuming.

**A7 — The `output` cap.** `output: Math.min(32_768, Math.max(4_096, ctx/2))`
appears in **four** places (`src/server/{llamacpp,openvino}/index.ts`, twice
each). Every model gets a 32768-token licence to think. This is why a 27B once
burned 30,639 tokens returning nothing, and it sets how long each occurrence of
the Laguna empty-response bug wastes. **Suggest capping at 8192. Never changed —
the user has not approved it.**

**A8 — Laguna empty-response bug.** On `/v1/chat/completions` with `--jinja`,
reasoning sometimes consumes the whole budget and `content` returns empty.
Reproduced **2 of 7** long-context runs **including on the old config**, so it
predates the retune. Upstream `ggml-org#25165`. Workaround per poolside: disable
thinking. Untested.

**A9 — OpenVINO backend is merged but unexercisable here.** No `ovms-serve`
binary, no servable, no `graph.pbtxt`, and the `setup-ovms.sh` that supposedly
creates one is in neither repo. Dormant code. Its `cache-size`/`cache-interval`
settings were removed this session (they were inert *and* the panel displayed a
false value); tuning happens in `graph.pbtxt`.

## 4. Key findings (all measured, with the file to quote)

**Laguna-S — the whole win was one unswept parameter.** Both recorded "ceilings"
were properties of **q8_0 KV**, which had never been varied. `cache-type-k/v` →
`q4_0` freed 552 MiB: enough for the **K16 rung nobody had tested** *and* +51%
context. K17 genuinely does not load.
→ `docs/laguna-retune-2026-07-27.md`

**Laguna-S decode is CPU-compute-bound**, not transfer-bound. Thread scaling
4.00 / 7.36 / 12.53 / 15.60 t/s at 1/2/4/6 threads proves it. Forcing expert
compute onto the GPU (`GGML_OP_OFFLOAD_MIN_BATCH=1`) is **45% slower** because
the CPU's route to those weights (DDR4 ~40 GB/s) is 5–10× wider than the GPU's
(PCIe 3.0 x8 ~7.9, x4 ~3.9). **K is the only decode lever.**

**Qwen 27B is a hybrid model** — `qwen35`, `full_attention_interval 4`,
`ssm.state_size 128`, 65 blocks → ~49 recurrent layers. Recurrent state cannot be
rewound, so on divergence the server falls back to the nearest **context
checkpoint**, not the longest common prefix. `n_prompt_tokens_cache` is assigned
*after* that pull-back — so a cache value of 52,670 does **not** mean the client
diverged there.
→ `docs/q27b-production-depth-2026-07-28.md`

**MTP does not compress at depth** (contradicting `mtp-27b.md` §3): acceptance
**0.847** and mean accepted length **3.54** at 64–128k, versus 0.573 / 2.71 at
32k. Decode 71.3 → 44.9 t/s with a **knee between 64k and 96k**; that is the base
step slowing.

**Dead ends, confirmed in source — do not retry:** `--cache-reuse` (silently
ignored on IMROPE models, and handles deletions not insertions), bounded
`--cache-ram` (one entry here is 8–9 GiB), `--cache-idle-slots` (irrelevant to a
single slot), `/slots restore` on hybrid (upstream #25913), DFlash (dead at every
n from 7 to 64 on poolside's own fork), ik_llama.cpp (allocates full-context KV
for all 48 Laguna layers — 4× the KV, OOMs), vLLM (4-bit floor is 60–67 GiB vs
32.6 GiB VRAM).

## 5. Traps — read before measuring anything

1. **`-ub` is silently clamped to `-b`** (`llama-context.cpp:264`), and `-b`
   defaults to 2048. `-ub 4096` alone does nothing. Set both. This invalidated a
   whole phase of this session's own sweep.
2. **Discard a warmup generation.** The first gen after load builds CUDA graphs.
   Measuring it produced a **60% discrepancy between two identical configs**
   (9.0 vs 14.4 t/s). With one warmup discarded and 4 repeats, spread is 0.1–1.3%.
3. **The server log is shared across every model the router starts.** A naive
   grep for `draft acceptance` returned 660 records including `mean len 32` —
   impossible at `n-max 3`. **Segment by PID.**
4. **Filter prefill samples before binning.** `prefill t/s = Δprocessed / Δt`, so
   cache-hit turns (≈370 tokens) divide a tiny numerator by fixed overhead and
   report ~20 t/s. Unfiltered, this dragged a real ~500 t/s median to 116 and
   produced a false "prefill collapses at depth".
5. **Always quote depth.** Laguna prefill is 570 t/s at 32k and 515 at 62k;
   decode 15.25 at 8k and 12.9 at 62k. The 27B is 71 t/s at 32k and 45 at 118k.
   A bare number is not a measurement.
6. **Quote the file, not the number.** The same 27B config reads 76.3 / 75.1 /
   62.1 t/s across three of the repo's own benches.
7. **`--fit` is disabled** by both `-ngl 99` and `split-mode tensor`. Nothing
   rescues an over-large `ctx-size` at runtime — it loads, then dies mid-prefill.
8. **`pgrep -f` / `pkill -f` match your own command line.** Cost four self-kills
   this session. Put orchestration in a script file.
9. **`--parallel 1` on the 27B means `kv_unified = false`**; Laguna runs 4 slots
   with `kv_unified = true` (shared pool, each slot can address the full window).
10. **Anything `.gguf` under `models-dir` becomes a selectable model.** A
    downloaded speculator draft appeared in `/models`. Keep drafts elsewhere.

## 7. Things this session got wrong

Recorded so they are not repeated or trusted.

- Claimed Laguna decode was **PCIe-transfer-bound**. It is CPU-compute-bound.
  The offload test showed the *transfer path* is expensive, which is the
  opposite inference. Corrected in the doc; thread scaling settled it.
- Reported **"prefill collapses to 115.9 t/s"** for the 27B. Binning artifact
  (trap #4). Real sustained prefill is ~500–570 t/s.
- Predicted **DFlash would work above the 32-token offload threshold**. Built
  poolside's fork specifically to test it. Falsified — dead at every n.
- Added a `/localhost` option to a `DialogSelect` whose text box is a *filter*,
  so typing an address filtered away the row you needed. Another agent found and
  fixed it.
- Told the user an OVMS bug report "didn't describe this project" — correct at
  the time, superseded minutes later when the branch was pushed.
- Restarted a live server without asking, and raised a build to `-j 8` on a
  6-core box while a 37 GB model was loading, which crashed the machine.
